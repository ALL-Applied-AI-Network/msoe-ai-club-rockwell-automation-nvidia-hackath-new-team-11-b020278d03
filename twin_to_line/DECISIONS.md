# Team Ignite — Decisions

Durable engineering decisions. Change one only when new evidence contradicts it; then mark it superseded and add a new ID.

| ID | Decision | Reason | Date |

| D001 | Stay on Dataset 1 (Final Vial Inspection). | Twin + camera match the real station; switching costs more than it gains. Dataset 2 scored close (78 vs 92) but loses on switching cost. | 2026-10-13 |
| D002 | The product is commissioning / changeover speed, not "AI crooked-cap detection". Claim: the twin eliminates or sharply reduces the real defect data and line time needed to commission inspection. | Cap presence/tilt checks are commodity (Keyence, Cognex). Cutting real defect collection per changeover is not. | 2026-10-13 |
| D003 | Primary experiment is synthetic-only training (zero real images). Zero is the best possible result, not a hard requirement. | Measures the strongest version of the claim first. Organizers allow real data (Tanner, Oct 13: "up to you"), so this is our choice. See D014. **"Organizers allow real data" is superseded by D025.** | 2026-10-13 |
| D004 | Initial scope is the Good fixture, G01–G30. | Escapes in G are the costly failure. The twin has no S hole map (only 5 scrap vials lying down). | 2026-10-13 |
| D005 | Target visible crooked caps of roughly ≥15–20°. | Twin geometry: cap edge moves ~2 px at 10°, ~3 px at 15°, ~4–4.5 px at 20°, ~7 px at 30° (cap ≈ 21 px wide). | 2026-10-13 |
| D006 | Subtle tilt (<~15°) and lifted-but-level caps are reported as a camera-resolution limit, not a target. | Lifted 5 mm = 0.3 px. A seated cap on a 2°-leaning vial moves 2.3 px, more than a 10° tilt. Needs a side view. | 2026-10-13 |
| D007 | Fill-sequence reasoning is core: an empty hole inside the placed prefix = missed placement; after it = waiting. (How the prefix is found without a placement count: D021.) | Single-frame checks cannot tell these apart; twin numbering G01–G30 already equals fill order. | 2026-10-13 |
| D008 | Cosmos / VLM is optional; it must earn its cost by rescuing uncertain cases measurably. | Throughput is low but VLMs are slow/costly and not needed for the core states. | 2026-10-13 |
| D009 | Do not generate a dataset or train before the Isaac Sim appearance gate (kit gate-v2.0). | Geometry is proven; appearance transfer is not. | 2026-10-13 |
| D010 | No personal Brev spending before official team access. | Team credits come via the organizers' captain link; the gate does not change the team plan. | 2026-10-13 |
| D011 | Real-data boundary. **Runs 1–3**: development/reference — visual inspection, sim-to-real comparison, sanity checks, auto-labeling review, and adaptation ONLY if D014 is triggered. **Runs 4–5**: model holdout — never used for classifier training, threshold tuning, prompt examples, augmentation decisions, choosing the synthetic-data recipe, or choosing a model because it does better on these runs. Some run 4–5 frames were used in the Oct 13 geometry registration, so they are a valid model holdout but not a pristine end-to-end evaluation. **New CSI deliberate-defect collection**: preferred final end-to-end evaluation; any adaptation subset from it is chosen in advance and kept physically/logically separate. Evaluation unit = placement event, not frame. | Frames ~2 s apart are near-duplicates; a run-level split prevents tuning on the test set. | 2026-10-13 |
| D012 | Defect authoring = small USD override layers over the untouched station file; labels are derived by re-reading the composed stage. | Reproducible, tiny (≈5 KB per scene), labels cannot drift from the scene. | 2026-10-13 |
| D013 | Liquid = a simple colored cylinder inside the vial (UsdPreviewSurface, opacity 0.85), no fluid sim. | From overhead, a capped vial hides the liquid; an uncapped vial reads as a dark grey-green top in real frames. | 2026-10-13 |
| D014 | If synthetic-only falls short, run a controlled data-efficiency experiment: add labeled real subsets from runs 1–3 of 5, 10 and 20 examples, chosen in advance and nested (each larger set contains the smaller), to the synthetic training; evaluate each on the same holdout; report performance vs. number of real examples. **Suspended by D025: not with supplied data (runs 1–5); with new CSI data only if organizers allow it.** | Turns the fallback into the headline curve ("how much real data the twin saves") instead of optimizing for a slogan. Tanner (Oct 13) confirmed any data mix is allowed. | 2026-10-13 |
| D015 | Twin USD geometry is the dimensional source of truth for vials, caps and fixtures. | Tanner (Oct 13): dimensions are preserved in the USD geometry, units and transforms. Our 3 px registration agrees. | 2026-10-13 |
| D016 | Real data request = a small hand-staged defect set on one filled G fixture (known tilt angles ~15/20/30°, missing caps, mid-sequence empties, all-good), not robot-filled runs. | Same evaluation value at a fraction of CSI line time; known angles also confirm the camera's crooked-cap limit. | 2026-10-13 |
| D017–D020 | Reserved. These IDs were referenced from another working session and are not in this repository; do not reuse them. | Avoids two different decisions sharing an ID. | 2026-10-16 |
| D021 | Runtime fill-sequence logic uses only visible occupancy plus optional temporal history; the line equipment provides no placement count or order-complete signal. Empty before the highest occupied position = MISSED; after it = WAITING (first one = frontier, WAITING by default, UNSURE optional); unreadable positions are UNSURE on their own and never move the frontier; `SequenceTracker` latches MISSED once a later vial persists; `complete=True` marks trailing empties MISSED. A count K is optional offline metadata or the camera's own event counter. | Derek Riley (Oct 16): count/complete signal not available. DEV runs 1–3: same false-positive count as the event-counted K (14), 31/32 vs 32/32 recall; the miss is an uncapped vial read as empty at the frontier, caught one placement later. | 2026-10-16 |
| D022 | G01–G30 is our own convention (the twin's numbering: G01 top-right, down the column, then one column left). Never state or imply it equals CSI's internal position numbers. | Derek Riley (Oct 16): CSI numbering differs and is not available. The organizers' labeling tool uses the same G01–G30 rule (verified: +3.6° rotation, no mirror). | 2026-10-16 |
| D023 | Crooked cap = any cap not fully seated (organizer definition). Our refinement: target visible tilt or displacement of roughly 15–20° or more; shallower tilt and level lift are reported as the overhead camera's information limit and confirmed with known-angle staged examples. | Derek Riley (Oct 16) allows a defined refinement; D005/D006 geometry (~2 px at 10°, ~3 px at 15°, ~4–4.5 px at 20°). | 2026-10-16 |
| D024 | The twin-derived position map is the runtime/commissioning source. Organizer coordinates are an independent validation reference only: the map is never tuned to them. | Self-validation is weak. Result: 30/30, 1.23 px median after a corner-only similarity into the organizers' 1920×1080 view (`validate_official_grid.py`). | 2026-10-16 |
| D025 | No model fitting on real images until organizers confirm the rule. Supplied real data (runs 1–5, the public release) is for looking, development and evaluation only. Training or fine-tuning on newly collected CSI data, and threshold calibration on real data, are pending. | Organizer guides: "The real data from the line is there to look at, not to train on"; "avoid training your models on them". Derek (Oct 16): confirm the training-data rules first. Supersedes D003's "organizers allow real data" and suspends D014. | 2026-10-16 |
| D026 | `damaged_vial` is explicitly out of scope for v1. It stays in the label vocabulary and the evaluation so any occurrence is still reported. | No confirmed example available locally; body damage is mostly hidden under the cap from overhead at 640×480; the twin cannot deform rigid tube meshes with override layers (D012). | 2026-10-16 |
| D027 | The NVIDIA vial labeler (Oct 14) is a manual adjudication tool for the 1920×1080 tray view, not an autolabeler. Workflow: our draft labels + human confirmation in the tool; never treat any single source as unquestioned ground truth. | It makes no class predictions and rejects 640×480 frames. | 2026-10-16 |
| D028 | Team reassignment (Noor → Code Crusaders, Oct 16): preserve the Team Ignite repository, its history and frozen artifacts; no migration, merge or push until Tom clarifies repository ownership and both teams' work has been compared. | The gate's pre-registration depends on commit history; the merged architecture is not chosen yet. | 2026-10-16 |
| D029 | A supervised live run during Session B counts as the real-hardware demonstration if our system runs on the real hardware. | Derek Riley (Oct 16). | 2026-10-16 |
