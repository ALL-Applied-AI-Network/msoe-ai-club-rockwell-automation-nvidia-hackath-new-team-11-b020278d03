## Arm B fitting: recovered procedure, no invented threshold rule

Original command: `python rules.py --fit labels/dev_labels.csv` (README); original implementation and artifact
arrived in commit `2e56ab0`. The ASTs of `_disk`, `features`, `decide`, and `fit` in current `rules.py` match that
commit exactly. `fit_rule_synth.py` calls those unchanged functions; it only adapts the input source and output path.

- Input: `train_v1/data_train` and `train_v1/data_tilt`, the recorded `crops.csv` **val** split only: 104 + 9 =
  **113 scenes, 3,390 arrangement-position crops**. Classes: pass 1,516; crooked 653; missing 547; no_vial 674.
- Camera/crops: full lens-applied twin renders at 640×480; `PositionMap(offset=(0, 0))` and `extract_crops`, matching
  `cut_train_crops.py`. No DEV offset, resizing, model augmentation, training-split pixels, or real-image fitting.
  The underlying render recipe was calibrated using DEV appearance; synthetic validation does not mean the
  entire development pipeline was free of real-data calibration.
- Features: original HSV yellow mask; cap fraction within radius 11 px, yellow-centroid offset within radius 13 px;
  the original rounding remains 4 decimal places for fraction and 2 for offset.
- Fitter: absent threshold = round(0.8 × minimum fraction among pass/crooked, 3). Search seated fraction
  0.20…0.94 in 0.02 steps and offset 2.0…8.0 in 0.1 steps. Reject any point accepting a labelled crooked cap as
  pass; maximize accepted pass caps; ties choose larger seated fraction, then smaller offset. No search changes.
- Result: **0.032 / 0.94 / 2.0**, written before G3 and never retuned. The JSON records manifest/render hashes,
  feature ranges, source-code hashes, counts, and zero offset. Existing threshold files are untouched.

Executed once from this worktree (commands are provenance, not a request to repeat G3):

## Freeze-prep part 2 — offline scoring and operator procedure

thresholds, maps, registration, warp or the gate. It runs exactly five operating points into `A_d038`,
`A_preregistered`, `B_synthetic`, `B_prime`, `B_double_prime`, injecting the corresponding existing inspector
into the unchanged `live_inspect.Session`: gate **each**, **LIVE_FILL**, **no tracker**, CPU by default.
The two A variants share the v1 weights; the three rule files are selected explicitly, never copied over one another.
Rule provenance identifies B as synthetic-validation fit and B′/B″ as DEV references, with the organizer question open.

Before image decoding or model loading, the wrapper requires an existing labels CSV and the full SHA256 supplied
with `--labels-sha256`. Its frame/position rows must reconcile exactly to every input image × 30 positions;
`usable=0` preserves locked exclusions. The output stores original image bytes and a byte-identical locked-label
snapshot, hashes, arm coverage and each runtime's provenance. Arm-occluded inputs are logged and not scored.
No thresholds are fitted and no arm is selected by these results. Metric analysis follows the frozen Dataset 1
protocol, including separate defect classes, false alarms, misses and escalation.

The persistent `results/sealed_score_locks` ledger is keyed by the sorted input-byte hashes; changing names,
labels or output directory cannot repeat the same set in this checkout. Existing output directories are refused.
A failed or interrupted evaluation keeps its lock and partial evidence: no automatic retry/resume. Never erase
or bypass the ledger in another checkout. This is an operational guard, not protection against deliberate dataset
modification. No sealed inputs exist or were scored in this task.
